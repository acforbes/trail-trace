# Trail Trace

Trail Trace analyzes GPX and TCX tracks with a FastAPI backend and a React,
Vite, and Leaflet frontend.

## Run locally

Install the Python dependencies and start the API:

```powershell
python -m pip install -r requirements.txt
python -m uvicorn backend.main:app --reload --port 8000
```

In another terminal, install the frontend dependencies and start Vite:

```powershell
Set-Location frontend
npm install
npm run dev
```

Open the Vite URL shown in the terminal. The development server proxies API
requests to `http://localhost:8000`.

## API

`POST /api/process-gps` accepts multipart form data:

- `file` (required): `.gpx` or `.tcx`, up to 25 MB
- `radius_meters` (optional): return radius; defaults to 20
- `start_time` (optional): ISO 8601 base time for tracks without timestamps
- `start_latitude` and `start_longitude` (optional): provide both to choose a
  lap start location; otherwise the first track point is used

The JSON response contains lap statistics, each lap's ordered coordinates, the
selected start location, the first track point's timestamp, and the number of
track points. It also contains best-fit route patterns generated by Extended
Kalman Filtering (EKF), smoothing splines, and cubic Bézier curves. Each
algorithm fits every lap, then selects the fitted lap with the lowest squared
error to the equal-distance consensus of all completed laps. Pattern lengths
are measured from the fitted route.

## Docker

Build and run the combined production frontend and API:

```powershell
docker build -t trail-trace .
docker run --rm -p 8000:8000 trail-trace
```

The React map keeps its Leaflet instance mounted while lap visibility changes,
so changing checkboxes updates route layers without resetting the viewport.
